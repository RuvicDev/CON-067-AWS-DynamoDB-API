¿Qué es y para qué sirve?

Este conector permite al agente de Ruvic operar directamente sobre una tabla de Amazon DynamoDB: escribir/reemplazar un ítem, obtenerlo por su clave, consultar por partition key, eliminarlo y describir la tabla.

Este conector escribe y elimina datos A diferencia de los conectores de solo consulta del catálogo, este SÍ escribe (put_item) y elimina (delete_item) ítems reales en la tabla configurada.
Operación Qué hace
dynamo.put_item Escribe o reemplaza por completo un ítem
dynamo.get_item Obtiene un ítem por su clave primaria
dynamo.query Consulta ítems que comparten una partition key
dynamo.delete_item Elimina un ítem por su clave primaria
dynamo.describe_table Metadatos de la tabla (estado, cantidad de ítems, tamaño)

Prerrequisitos

  • Una tabla de Amazon DynamoDB ya creada, con su clave primaria definida.
  • Acceso a la consola de AWS IAM para crear un usuario dedicado.
  • El nombre de la tabla y la región de AWS donde vive.

Configuración en el fabricante

Vas a crear un usuario IAM dedicado para Ruvic, con permisos limitados a una única tabla. No reutilices credenciales de administrador ni de tu aplicación.

  1. Crea un usuario IAM dedicado.

    En IAM → Usuarios → Crear usuario. No le des acceso a la consola, solo acceso programático.

  2. Crea una policy con el mínimo privilegio necesario.

    Adjuntá una policy en línea limitada a la tabla que va a usar el conector:

    {
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "dynamodb:PutItem",
        "dynamodb:GetItem",
        "dynamodb:Query",
        "dynamodb:DeleteItem",
        "dynamodb:DescribeTable"
      ],
      "Resource": [
        "arn:aws:dynamodb:*:*:table/mi-tabla",
        "arn:aws:dynamodb:*:*:table/mi-tabla/index/*"
      ]
    }
  ]
}
  3. Genera las claves de acceso.

    En la pestaña "Credenciales de seguridad" del usuario, creá un Access Key. Guardá el Access Key ID y el Secret Access Key — el secreto solo se muestra una vez.

Permisos requeridos

Permiso Para qué sirve
dynamodb:PutItem Escribir/reemplazar ítems (put_item)
dynamodb:GetItem Leer un ítem por clave (get_item)
dynamodb:Query Consultar por partition key (query)
dynamodb:DeleteItem Eliminar un ítem (delete_item)
dynamodb:DescribeTable Metadatos de la tabla (describe_table, test de conexión)
Nota No se otorgan permisos de administración de tabla (dynamodb:CreateTable, dynamodb:DeleteTable, dynamodb:UpdateTable).

Configuración en Ruvic

Entrá a Settings → Conectores, buscá la tarjeta AWS DynamoDB API y pulsá Configurar.

Campo del formulario Valor
Access Key ID El Access Key ID generado en el paso anterior
Secret Access Key El Secret Access Key generado (se guarda cifrado)
Región de AWS La región donde está la tabla (ej. us-east-1)
Tabla Nombre exacto de la tabla DynamoDB

Probar conexión — la plataforma describirá la tabla configurada para confirmar credenciales y acceso.

Verificación

  1. Test de conexión exitoso.

    El botón "Probar conexión" debe responder con éxito describiendo la tabla configurada.

  2. Prueba mínima con el agente.

    Abrí una conversación nueva y pedile:

    "Describime la tabla DynamoDB configurada."

    El agente debe devolver el estado real y la cantidad de ítems de la tabla.

Solución de problemas

Mensaje / síntoma Causa probable y solución
"Credenciales inválidas o sin permiso IAM suficiente" Access Key inválida/rotada, o la policy no incluye el permiso necesario para la operación. Revisá la policy adjunta al usuario IAM.
"La tabla no existe o no es accesible" Nombre de tabla mal escrito, o la tabla está en otra región distinta a la configurada.
"No se pudo conectar al servicio" (timeout) Región de AWS incorrecta, o problema de red temporal. Reintentá.
"La condición de la escritura no se cumplió" Error interno poco común en este conector (no usa condiciones de escritura); reportalo si aparece.
El conector aparece "Sin configurar" tras guardar Algún campo obligatorio quedó vacío. Completá Access Key ID, Secret Access Key, Región y Tabla.

Preguntas frecuentes y notas de seguridad

¿El agente puede modificar o borrar cualquier tabla de mi cuenta de AWS?

No. La policy IAM del usuario dedicado se limita a la tabla configurada — el agente no puede acceder a otras tablas de la cuenta.

¿Dónde queda guardado el Secret Access Key?

Como secreto en el almacén de credenciales de la plataforma. La interfaz nunca vuelve a mostrarlo; solo indica "definido". Para cambiarlo, escribí uno nuevo en el formulario.

Rotación de credenciales

Recomendado cada 90 días: generá un Access Key nuevo en IAM, actualizalo en el formulario del conector, y desactivá/eliminá el anterior una vez confirmado que el nuevo funciona.

¿Qué hago si las claves se comprometen?

  1. Desactivá el Access Key inmediatamente en IAM.
  2. Revisá la actividad reciente en AWS CloudTrail.
  3. Generá un Access Key nuevo y actualizalo en el formulario.
Buenas prácticas Usá siempre un usuario IAM dedicado y limitado a una sola tabla; nunca reutilices credenciales de administrador; y recordá que put_item/delete_item modifican datos reales de producción si apuntás el conector a una tabla productiva.
